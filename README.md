# Sustainability Headline Relevance Classifier

A binary text classifier that decides whether a news headline is **relevant to environmental sustainability** (label `1`) or **not relevant** (label `0`). It is built entirely from scratch: no pretrained weights (no BERT, no GloVe) and no fine-tuning. The repository covers the full pipeline: collecting headlines from Google News RSS, training and evaluating two models, and running the saved model on new headlines.

> **Scope and disclaimer.** All data (training and study set) is **English-language news headlines from the US and India editions of Google News**. The model has not been tested on other languages or on headlines from other regions, and its results should not be assumed to carry over to them: other countries use different place names, institutions, policies and phrasing that the model has never seen.

## Label definition

| Label | Name           | Meaning                                                                                                                                                                                                                       |
| ----- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | `relevant`     | The headline's main subject is the environment, climate, or environmental sustainability (emissions, energy transition, pollution, waste and recycling, nature and conservation, environmental impact of business or policy). |
| 0     | `not_relevant` | Everything else. This includes social topics (labor, DEI, human rights), governance, and pure market news (oil prices, EV stock moves) with no environmental angle.                                                           |

Weather and disaster coverage follows a narrow rule: a flood, storm or fire headline is `relevant` only if it ties the event to an environmental cause, impact, pollution or policy (for example wildfire smoke and air quality, or a climate attribution study). A plain weather or incident report (a nor'easter hitting a city, a fire at a recycling plant) is `not_relevant`.

Negatives come in three kinds so the model has to learn the concept, not just keywords:

- **Hard negatives:** the same words used in a different sense ("political climate", "Miami Heat", "clean sheet", "carbon fibre bike").
- **Adjacent negatives:** nearby but non-environmental topics (executive pay, Tesla earnings, labor strikes).
- **Easy negatives:** general news (sports, entertainment, finance, politics).

## Pipeline, in order

### 1. Collect the training data

Queries Google News RSS (English, US and India) using a list of positive and negative keywords. Each keyword gets an equal share of the target, and the script moves to the next keyword once its quota is met.

```bash
python collect_news.py --small --end-date 2026-06-30
```

Writes `data_small/small_combined.csv` (about 3,000 rows per label). Useful options: `--dry-run` (show the plan without any requests), `--target-rows`, `--years`.

### 2. Check and clean the labels by hand

Labels come from the search keyword, so some are wrong. Review the CSV and fix them before training. The file used for the results below is `small_combined_clean.csv`.

### 3. Build a held-out validation set

A later time window, with every headline already used for training removed.

```bash
python collect_news.py --validation
```

Writes `data_validation/validation_participant.csv` (`id`, `title` only, safe to share with annotators) and `validation_ground_truth.csv` (keep private; review it by hand before use).

### 4. Train and evaluate

Only the `title` and `label` columns are needed.

```bash
python train_model.py --data small_combined_clean.csv --out model_out
```

If the CSV also has a keyword column (`base_query` or `query`), the data is split **by keyword** (70/15/15), so the test set contains keywords the model never saw. Use `--split random` for an easier random split. The decision threshold is tuned on the validation split to reach a precision target (`--precision-target`, default 0.95).

Outputs in `model_out/`:

- `logreg/`, `nn/`: the saved models, and `model_card.json` (best model, thresholds, metrics)
- `eval/`: `metrics.csv`, `test_predictions.csv`, and charts for the confusion matrix, ROC curve, precision-recall curve, score distribution, accuracy by tier and the neural net's training curve

### 5. Run the model

```bash
python test_model.py                                   # interactive
python test_model.py --text "Delhi AQI turns severe" "Miami Heat beat Celtics"
python test_model.py --csv headlines.csv               # scores a CSV; adds metrics if it has a label column
python test_model.py --threshold 0.5 --text "Delhi AQI turns severe"   # override the saved threshold for one run
```

### 6. Evaluate on a separate study set and analyse errors

Run the saved model over a labelled set that was never used for training (needs `title` and `label` columns; `tier`, `region` and `keyword` columns add breakdowns). Quote paths that contain spaces.

```bash
python evaluate_study.py --data validation_ground_truth.csv --out study_eval
python evaluate_study.py --data validation_ground_truth.csv --threshold 0.8 --out study_eval_after_080
```

It writes the submission file (`study_dataset_submission.csv`: headline, model score and label, ground truth), metrics with 95% bootstrap intervals, error rates by tier, region, keyword and model confidence, and `errors_to_tag.csv`. Fill in `manual_pattern` there by hand and run it again: your tags are kept (matched by `id`) and `error_distribution.csv` and `.png` (pattern, number of errors, % of all errors) are rebuilt. Close the CSV in Excel before re-running, or Windows will refuse the write.

From Python (for example, in a web service):

```python
from relevance_model import RelevanceClassifier

clf = RelevanceClassifier.load("model_out")            # best model, tuned threshold
clf.predict(["Delhi AQI turns severe as stubble burning rises"])
# [{'title': ..., 'score': 0.99, 'label': 1, 'label_name': 'relevant'}]
```

Options: `RelevanceClassifier.load("model_out", model="nn")` selects the neural net, and `clf.predict(titles, threshold=0.5)` overrides the threshold. The neural net needs only `numpy` and `scipy` at inference time.

## Approach

1. **Data:** headlines are deduplicated, and any title that appears with both labels is dropped.
2. **Features:** lowercase words and word pairs (bigrams) for the neural net; word and character n-gram TF-IDF for the baseline. Vocabularies are built from the training split only.
3. **Models (both trained from random initialisation):**
   - _TF-IDF + logistic regression_ (scikit-learn), with the regularisation strength chosen on validation.
   - _From-scratch neural net_ written in NumPy with hand-coded backpropagation and the Adam optimiser. It averages learned word and bigram embeddings, passes them through a ReLU hidden layer, and outputs a probability. It uses dropout and random word dropout, and stops early on validation loss. The gradients were checked against numerical gradients.
4. **Threshold:** because letting an irrelevant headline through is the costlier error, the threshold is tuned on validation to hit a precision target. Metrics are reported at both 0.5 and the tuned threshold.
5. **Model choice:** the best model is selected by validation PR-AUC and recorded in `model_card.json`.

## Results

Evaluated on a held-out test set of 868 headlines whose keywords were **not seen in training**, which is a stricter test than a random split.

| Model                        | Threshold                  | Accuracy | Precision | Recall | F1    | ROC-AUC |
| ---------------------------- | -------------------------- | -------- | --------- | ------ | ----- | ------- |
| TF-IDF + logistic regression | 0.50                       | 0.863    | 0.859     | 0.853  | 0.856 | 0.941   |
| TF-IDF + logistic regression | 0.88 (tuned on validation) | 0.786    | 0.949     | 0.582  | 0.722 | 0.941   |
| From-scratch neural net      | 0.50                       | 0.873    | 0.852     | 0.889  | 0.870 | 0.936   |
| From-scratch neural net      | 0.83 (tuned)               | 0.809    | 0.913     | 0.662  | 0.768 | 0.936   |

More charts (neural-net confusion matrix, score distribution, accuracy by tier, training curve) are in `model_out/eval/`.

- The two models perform about the same (the accuracy gap is within the margin of error for this test size).
- Tuning for high precision costs a large share of recall: to reach about 95% precision, logistic regression recovers 58% of the relevant headlines.
- Negatives are handled well (easy 100%, adjacent 99%, hard 95% at the tuned threshold). Most errors are relevant headlines that get missed.

### Study-set evaluation and threshold change

The saved models were also scored on a separate 298-headline study set (140 relevant, 158 not relevant; collected from a later time window, with every training headline removed; never used for training or tuning the model weights). Its keywords overlap with training, so it is easier than the held-out-keyword test above.

| Logistic regression threshold | Accuracy | Precision | Recall | F1    | Errors (FP / FN) |
| ----------------------------- | -------- | --------- | ------ | ----- | ---------------- |
| 0.50                          | 0.899    | 0.910     | 0.871  | 0.891 | 30 (12 / 18)     |
| 0.88 (tuned on validation)    | 0.826    | 0.978     | 0.643  | 0.776 | 52 (2 / 50)      |
| **0.80 (saved)**              | 0.859    | 0.962     | 0.729  | 0.829 | 42 (4 / 38)      |

ROC-AUC 0.970, PR-AUC 0.966. At 0.80 the 95% bootstrap intervals are precision 0.924 to 0.991 and recall 0.657 to 0.800.

Most of the misses at 0.88 scored between 0.5 and 0.88, so the loss of recall came from the cut-off, not the model. After seeing these results the saved threshold was lowered from 0.88 to 0.80 (no retraining; the study set was not added to the training data). The 0.80 figures are therefore slightly optimistic, and on new topics precision will likely be lower: at 0.88 the held-out-keyword test already gave 0.949.

Error pattern distribution at 0.80 (42 errors): political, legal or policy framing 21.4%; acronyms, jargon or technical wording 16.7%; implicit, figurative or local-impact headlines 16.7%; borderline labels 14.3%; business, finance or jobs framing 7.1%; EV and electric-transport topics 7.1%; wildfire-smoke or extreme-weather coverage 7.1%; false positives (adjacent topic, or environmental word used in a non-environmental sense) 9.5%. 90.5% of all errors are relevant headlines the model missed.

## Limitations

- Labels start as weak labels from search keywords, then were checked by hand. Some noise remains.
- English only, US and India editions, headlines from 2024 to mid-2026.
- Training data and the study set are each roughly 50/50. A real news feed is mostly irrelevant, so expect lower precision in production unless the threshold is adjusted for that (on the study set, estimated precision at 0.80 falls from 0.96 to about 0.76 if only 10% of headlines are relevant).
- Relevant headlines that use no environmental wording (political or policy framing, figurative language, acronyms such as SFDR or CCAMLR) are the main failure mode.
- Headlines only (no article text), and a small vocabulary learned from scratch means new names and events can be missed.

## Data note

Headlines were collected from Google News RSS and are included here only as the training data for a class assignment (non-commercial, educational use). The headlines remain the property of their original publishers. The held-out validation set used for the annotation task is not published, so that it stays a fair test. `collect_news.py` rebuilds a comparable dataset.
